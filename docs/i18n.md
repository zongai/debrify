# App language (i18n)

Debrify ships a lightweight localization layer under `lib/l10n/`.

## Supported UI languages

- English (`en`) — default fallback
- Chinese (`zh`)
- Japanese (`ja`)
- System — follow the device locale when it matches a supported language

## User setting

**Settings → Appearance → Language** (or Settings search: `Language` / `中文`)

Preference is stored as `app_language` (`system` | `en` | `zh` | `ja`).

## Adding strings

Two styles (both valid):

1. **Named keys** — add the same key to `_tables` for `en` / `zh` / `ja`, expose a getter, use `AppLocalizations.of(context).yourKey`.
2. **Phrase table** — map English UI source → translation in `_phraseTables['zh']` (and optionally `ja`), use `AppLocalizations.of(context).t('English source')`.

`SettingsTile` / `SettingsSection` already call `t()` on titles and blurbs when the locale is not English. Keep `SettingsRows` titles as English **string literals** (they are translated at display time).

Material / Cupertino framework strings come from `flutter_localizations`.

## Scan hardcoded English (P0)

```bash
python3 tool/scan_i18n_hardcoded.py
# default output: docs/i18n-untranslated-inventory.md

python3 tool/scan_i18n_hardcoded.py --module player --module iptv
python3 tool/scan_i18n_hardcoded.py --json /tmp/i18n-scan.json
```

Heuristic only: may miss interpolations and `Text.rich`. Re-run after each batch.
